# 🍅 ポモドーロ・タスク管理システム 運用仕様書

本リポジトリは、Markdownとポモドーロ・テクニックを組み合わせた、エンジニア向けのタスク管理システムです。

## 1. ファイル構成
- `Stock.md`: 全タスクのバックログ（時間軸・ルーチン管理）。※Stock_sample.mdからsampleを削除して利用
- `Daily/YYYY-MM-DD.md`: その日の実行ログ・作業メモ。
- `README.md`: 本仕様書。
- `TIPS.md`: VS Code効率化テクニック集。

---

## 2. タスク記述構文
環境に依存せず、検索・置換が容易なASCIIベースの記法を採用します。

### 2.1 基本書式
`- [ ] タスク名 [p][p] {due:属性}`

### 2.2 構成要素
| 要素 | 記述 | 意味 |
| :--- | :--- | :--- |
| **ステータス** | `[ ]` | 未完了。完了時は `[x]` に変更。 |
| **予定 (Planned)** | `[p]` | lowercaseの `p`。1個 = 25分。 |
| **実績 (Performed)** | `[P]` | uppercaseの `P`。完了したポモドーロ分を置換。 |
| **締切・曜日属性** | `{due:...}` | 以下の形式で指定する。 |

### 2.3 締切（due）タグのバリエーション
- **特定日**: `{due:2026-01-15}`
- **曜日指定**: `{due:MON}`, `{due:TUE}`, `{due:WED}`, `{due:THU}`, `{due:FRI}`, `{due:SAT}`, `{due:SUN}`
- **未定**: `{due:NONE}`

## 3. タスク種別と運用ルール

### 3.1 種別の定義
| 種別 | 配置セクション | 週末の扱い |
| :--- | :--- | :--- |
| **ルーチン (Routine)** | 各時間軸の `(Routine)` セクション | **リセット**: `[P]` を `[p]` に戻して翌週分とする。 |
| **単発 (Ad-hoc)** | 各時間軸の `(Specific)` セクション | **削除**: 完了（すべて[P]）した行を削除。 |

### 3.2 曜日指定タスクの扱い
`Weekly (Routine)` セクション等に配置し、`{due:MON}` のように指定します。
朝の `Stock.md` 確認時に、該当する曜日のタスクを `Daily.md` へ転記します。

---

## 4. 運用フロー

### 4.1 日次 (Daily Cycle)
1. **朝 (Setup)**: `Stock.md` を開き、今日やるべきタスク（曜日指定タスク含む）を `Daily.md` へコピーする。
2. **日中 (Execute)**: 実行ログは `Daily.md` でのみ更新。ポモドーロ完了ごとに `p` → `P` に置換。
3. **夕 (Sync)**: 
    - `Daily.md` での実績（Pの数）を `Stock.md` 側にも反映させる。
    - 割り込みメモを `Stock.md` の適切なセクションへ正規書式で転記する。

### 4.2 週末メンテナンス (Weekly Review)
1. **実績確認**: `Stock.md` を見渡し、一週間の総ポモドーロ数（Pの数）を確認・振り返る。
2. **単発タスクの削除**: 完了した単発タスク（`[x]` または `[P]` がある行）を一括削除。

## ⚡ 突発タスク・割り込みの運用ルール

業務特性（急な相談・トラブル対応等）を考慮し、割り込みを以下の3パターンで管理します。

### 1. 「あとでやる」割り込み (記録のみ)
作業中に発生したが、今すぐ着手する必要がないもの。
- **対応**: 実行中の `Daily.md` の「📝 メモ」欄にキーワードのみ即座に記入する。
- **目的**: 脳のワーキングメモリを解放し、今のポモドーロに集中し直す。

### 2. 「今すぐやる」割り込み (今日実行)
今日中に対応が必要で、ポモドーロを割り当てるもの。
- **対応**: `Daily.md` のタスク欄に直接追記し、先頭に `【突発】` を付与する。
- **例**: `- [ ] 【突発】〇〇サーバー再起動対応 [P] {due:2026-01-12}`
- **目的**: 予定外の作業にどれだけ時間（P）を割いたかを可視化する。

### 3. 「強制中断」 (タイムライン記録)
電話や対面での相談など、25分のタイマーが維持できなかったもの。
- **対応**: タイムライン上で `[!]` や `[-]` 記号を使い、中断されたことを記録する。
- **例**: `- 10:30 - 10:45 [!] (緊急障害対応により中断)`
- **目的**: 「自分の見積もりが甘かったのか、外部要因で物理的に無理だったのか」を週末に正しく評価するため。
